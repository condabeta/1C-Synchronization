# Наценка: автоматический расчёт розничной цены

Поставщики присылают свою цену, на сайте нужна розничная. Коэффициент задаёт
клиент — для одних поставщиков один на весь прайс, для других свой на категорию.
Правила лежат в таблице `supplier_pricing_rules`, поэтому смена коэффициента —
это правка строки в БД плюс пересчёт, а не изменение кода.

Источник требований: письмо клиента и вики svetoyar.pro,
Производители/поставщики → Наценка.

## Действующие правила

| Поставщик | Категория | База | Коэф. |
|---|---|---|---|
| Салюкс (`salux`) | все товары | колонка «Дистрибьютор» | **1.6** |
| LED Crystal (`crystal`) | СВЕТОДИОДНЫЕ ЛЕНТЫ | цена из прайса | **2.0** |
| LED Crystal | все остальные | цена из прайса | **1.5** |
| Jazzway (`jazzway`) | все разделы | цена клиента | **1.5** |
| ViaSvet (`viasvet`) | все товары | **колонка РРЦ**, без наценки | 1.0 |
| Декомо, SWG, Арлайт | правил нет | цена не пересчитывается | — |

### Салюкс: какая цена берётся за базу

Прайс Салюкса содержит четыре колонки цен — Розница, Опт, Дилер, Дистрибьютор.
Базой взята **«Дистрибьютор»** — клиент подтвердил это 15.09.2026: «наша цена на
сайте — цена дистрибьютера × 1,6».

Данные это подтверждают независимо. Собственный прайс Светояра на товары Салюкса
(`светнн1.xlsx`, см. `own_articles`) содержит колонку «Цена для дилера», и
медиана её отношения к колонке «Дистрибьютор» Салюкса равна **1.000** — то есть
это одна и та же закупочная цена. В том же файле есть готовая колонка «Цена для
дилера*1,6», и наш расчёт совпадает с ней на 553 строках из 557 (расхождения —
0.2–0.4 ₽ от округления).

Сменить базу для Салюкса — константа `BASE_TIER` в
`staging/importers/salux.py`. Остальные три уровня цен всё равно сохраняются
в `attributes_json` (`price_розница`, `price_опт`, `price_дилер`,
`price_дистрибьютор`).

Декомо присылает готовую МРЦ/РРЦ, поэтому наценка к нему не применяется. Если
клиент задаст коэффициент и для него — достаточно добавить строку в таблицу.

## Как это работает

```
прайс поставщика ──► supplier_products.price        (цена поставщика, как в файле)
                            │
                  supplier_pricing_rules            (коэффициент по категории)
                            ▼
                  supplier_products.price_retail    (розничная цена)
                            │  модерация / слияние
                            ▼
                  products.price_retail             (цена в каталоге)
```

* `price` — всегда то, что прислал поставщик. Не пересчитывается никогда.
* `price_retail` — результат применения правила.
* `pricing_rule_id` — какое именно правило дало эту цену (для отчётов и разбора
  «почему такая цена»).

Расчёт выполняется в `staging/pricing.py` и вызывается из
`staging/importers/common.py::upsert_product_batch` — единственного места, через
которое проходят все импортёры, — и из собственного upsert Декомо. То есть новый
импортёр получает наценку автоматически, без дополнительного кода.

## Как выбирается правило

1. Сортировка по `priority` (меньше — раньше).
2. При равном приоритете конкретное правило важнее правила «на всё остальное».
3. При прочих равных выигрывает более длинная подстрока.

Поэтому «Трековые системы» (приоритет 10) обходит «Светильники» (приоритет 50),
хотя трековые лежат внутри раздела светильников.

Сравнение — регистронезависимое вхождение подстроки в
`supplier_category_path + supplier_category`. Латинские буквы-двойники
(`C`, `o`, `p`, `e`, …) приводятся к кириллице: прайс Jazzway пишет свой раздел
как «**C**ветильники» с латинской C, и без этого одно правило промахнулось бы
мимо целого раздела.

## Откуда берётся категория

| Поставщик | Категория |
|---|---|
| LED Crystal | имя листа Excel («СВЕТОДИОДНЫЕ ЛЕНТЫ», «АКСЕССУАРЫ», …) |
| Jazzway | строки-заголовки разделов внутри прайса (см. ниже) |
| Декомо | колонка «Группа товара» |
| SWG | `categoryId` из YML |
| ViaSvet | имя листа |
| Салюкс | лист + заголовок блока («ССдС / Светильники судовые Флагман ССдС») |

### Jazzway: дерево разделов из самого прайса

В прайс-файле Jazzway категория не вынесена в колонку — она задана строками-
заголовками, у которых заполнен «Артикул», но нет «Номенклатуры» и цены:

```
 С В Е Т
.  1.  Cветильники
1. 3. Трековые системы
1.3.1. Трековые системы однофазные
```

`SectionTracker` в `staging/importers/jazzway.py` восстанавливает по ним путь
(«СВЕТ / Cветильники / Трековые системы / Трековые системы однофазные»), глубина
берётся из нумерации. Раньше категория подтягивалась только из YML-фида и только
для тех позиций, которые с ним сматчились; теперь категория есть у **всех** 2845
товарных строк прайса, что и требуется для наценки по категориям.

## Установка

```bash
mysql -u root -p svetoyar_staging < database/add_pricing_rules.sql
```

Пока миграция не применена, импорт не падает: он выводит предупреждение и
работает без наценки.

## Изменение коэффициента

```sql
UPDATE supplier_pricing_rules
SET coefficient = 1.7000
WHERE supplier_id = (SELECT id FROM suppliers WHERE code = 'salux')
  AND match_type = 'all';
```

затем пересчёт уже загруженных цен:

```bash
python scripts/recalc_prices.py --supplier salux --dry-run   # посмотреть
python scripts/recalc_prices.py --supplier salux             # применить
```

Пересчёт обновляет `supplier_products.price_retail`, карточки в `products` и
`product_supplier_offers`.

## Новое правило на категорию

```sql
INSERT INTO supplier_pricing_rules
  (supplier_id, rule_name, match_type, match_value, base_field, coefficient, priority)
SELECT id, 'Ленты x1.4', 'category', 'светодиодная лента', 'price', 1.4000, 20
FROM suppliers WHERE code = 'jazzway';
```

Прежде чем задавать подстроку, посмотрите, как категория действительно называется
у поставщика:

```bash
python scripts/recalc_prices.py --supplier jazzway --list-categories
```

Команда печатает все категории поставщика, количество товаров и правило, под
которое каждая из них попадает.

## Округление

Клиент выбрал цены без копеек (17.09.2026), поэтому у всех правил `round_to =
1.00` — округление до рубля. Чтобы вернуть копейки, обнулите `round_to`, чтобы
округлять до десяти рублей — поставьте 10.00:

```sql
UPDATE supplier_pricing_rules SET round_to = 1.00 WHERE supplier_id = ...;
```

## Что осталось уточнить у клиента

1. ~~**Салюкс, база цены**~~ — подтверждено клиентом 15.09.2026: цена
   дистрибьютора × 1,6. Настроено именно так.
2. **Салюкс, неуникальные маркировки** — в прайсе 102 позиции делят маркировку
   с другой позицией. Например `ССдО 03-040-003 IP20 "Офис 40"` — это и
   светильник 595х595х40 за 2 250 ₽, и 1200х180х40 за 3 520 ₽. Импортёр
   разводит их, дописывая к артикулу отличающийся признак:
   `ССдО 03-040-003 IP20 "Офис 40" [1200х180х40]`. Клиент подтвердил, что их
   собственные артикулы с артикулами Салюкса не совпадают, и обещал прислать
   полный прайс — он и станет основным ключом (см. `own_articles`).
3. ~~**Салюкс, «Агат 1Ех»**~~ — разъяснено клиентом 21.09.2026: это **разные
   светильники** с одной маркировкой. На листе «ССдС» — судовой взрывозащищённый
   «Агат» (14 962 ₽), на листе «ССдВз 1Ех» — взрывозащищённый «Агат» (14 250 ₽).
   Импортёр разводит их суффиксом листа в артикуле, цены у каждого свои, фото и
   описание берутся с разных страниц сайта Салюкса.
4. **Салюкс, лист «ССдО Линия»** — четвёртая колонка цен подписана «Старая
   Цена», а не «Дистрибьютор», при том же порядке величин. Считаем её ценой
   дистрибьютора. Так ли это?
5. ~~**Салюкс, «Дополнительные опции»**~~ — закрыто 22.09.2026. Юлия: матовость,
   цветовая температура и подобное менеджеры прописывают при заказе напрямую в
   Салюкс. Значит, это не товары и не свойства карточки — оставляем как есть,
   отдельным листом в прайсе.
6. **Свои артикулы на товары Салюкса.** Юлия подтвердила 22.09.2026: в 1С Fresh
   артикул — наш («000001»), маркировка Салюкса пишется в комментарии. Поэтому
   наш артикул проставляется в `products.onec_code` и уходит в 1С как «Артикул»,
   а маркировка — реквизитом «Маркировка поставщика».

   Проставлено у 269 товаров. Ещё 34 маркировки совпадают с несколькими нашими
   артикулами — их не трогаем, нужен человек. И 234 позиции Салюкса своего
   артикула не имеют вовсе: без него их нельзя завести в 1С, поэтому более
   полный прайс с нашими номерами всё ещё нужен.
7. **Jazzway, «Блоки питания»** — в прайсе такого раздела нет, ближайший
   «4.6. БП, контроллеры, акс-ры для светодиодной ленты» (сейчас ловится
   правилом ×1.5). Имелись ли в виду именно они?
8. **Jazzway, «3. Специальные светильники и лампы»** — раздел содержит и то и
   другое; сейчас применяется ×1.35 (как к лампам).
9. **Jazzway, светодиодная лента и профиль** — в списке клиента не названы,
   сейчас идут по общему ×1.25.
10. **LED Crystal, лист «РАСПРОДАЖА»** — ленты внутри него получат ×1.5, а не
    ×2, потому что лист не «СВЕТОДИОДНЫЕ ЛЕНТЫ». Нужно ли выделять?
11. **ViaSvet** — если в строке прайса РРЦ не заполнена, сейчас берётся
    «Ваша цена» без наценки. Какой коэффициент применять в этом случае?
12. **Округление** — оставляем копейки или округляем до рубля? Цены Салюкса в
    прайсе дробные (3 882.32 ₽), после ×1.6 получается 6 211.71 ₽.

## Файлы прайсов

Прайс Салюкса и собственный прайс Светояра пришли 08.09.2026 с расширением
`.pdf`, хотя это XLSX-книги, и были переименованы 12.09.2026. Файл Светояра

## Свои артикулы (`own_articles`)

Файл `светнн1.xlsx` — не прайс поставщика, а собственный прайс Светояра на
товары производства Салюкса. Он даёт наш артикул и наше наименование, которые
привязываются к позициям Салюкса по маркировке. Загрузка:

```bash
python scripts/import_own_articles.py --dry-run
python scripts/import_own_articles.py
```

Подробности — в шапке `database/add_own_articles.sql`.
