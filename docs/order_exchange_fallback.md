# Заказы с сайта без расширения (запасной вариант)

Если в их 1С:Fresh нельзя загрузить расширение (нет конфигуратора, Павел
25.11.2026), автоматически заводить карточку на каждого покупателя не получится.
Этот вариант обходится штатными средствами: заказы приходят на одного общего
контрагента «Розничный покупатель», а телефон, email и имя покупателя видны в
комментарии к заказу. Сотрудник при обработке заводит или находит реальную
карточку сам. Так проверено 20.11.2026 (заказ ИМ-007028 загрузился штатно).

## Настройки мастера обмена (1С)

Раздел CRM → «Обмен с интернет-магазином» (или «Обмены с сайтами»),
тип магазина — «Другой» (CommerceML).

| Параметр | Значение |
|---|---|
| Тип магазина | Другой (CommerceML 2) |
| Адрес обмена | тест: `https://svetoyar.pro/test/1c_exchange.php`; рабочий: `https://svetoyar.pro/1c_exchange.php` |
| Логин / пароль | как в `1c_exchange.cfg.php` на сервере |
| Выгрузка товаров, цен, остатков 1С → сайт | **выключить** (каталог на сайт идёт отдельно, 1С его не трогает) |
| Загрузка заказов сайт → 1С | **включить** |
| Организация | Светояр |
| Склад | Основной склад |
| Контрагент | «Не искать, подставлять выбранного» → **Розничный покупатель** |
| Статусы, способы доставки, способы оплаты | не сопоставлять (выключить) |
| Префикс номеров | ИМ |
| Расписание | на тесте — вручную; на рабочем — по расписанию |

Заказ приходит в состоянии «Не обработан», без резерва и без оплаты. НДС
подставляет организация (Светояр 5%).

## Что видит сотрудник

В каждом заказе в поле «Комментарий»:

```
Заказ с сайта №12345. Покупатель: Иван Иванов, тел. +79161234567, email ivan@example.ru. <комментарий покупателя>
```

Телефон всегда в формате +7XXXXXXXXXX. Это и есть требование Анны, чтобы телефон
и email попадали в базу: в режиме одного контрагента 1С отбрасывает блок контактов
из заказа и оставляет только комментарий, поэтому контакты продублированы в него.

## Обработка заказа сотрудником

1. Открыть заказ ИМ-…, в комментарии взять имя, телефон, email.
2. Найти контрагента по телефону (основной признак, в базе бывают дубли).
   - Нашёлся — подставить его в заказ вместо «Розничного покупателя».
   - Не нашёлся — завести нового: физлицо, группа «Покупатели»,
     тег «Конечный покупатель», вписать телефон и email.
3. Дальше обрабатывать заказ как обычно.

## Ограничения этого варианта

- Карточка покупателя создаётся **вручную**, не автоматически.
- Дубли по телефону сотрудник проверяет сам.
- Если позже их Fresh разрешит штатную загрузку расширения или тег окажется
  необязательным — вернёмся к автоматическому варианту (см. `onec_extension/`).

## Нужно сделать в коде

Файл `exchange/1c_exchange.php` уже пишет имя, телефон и email в комментарий
(добавлено 25.11.2026). Его нужно **повторно загрузить** на тестовый сайт тем же
способом (scp + подмена с резервной копией), после чего прогнать тестовый заказ и
проверить, что контакты видны в комментарии в 1С.
